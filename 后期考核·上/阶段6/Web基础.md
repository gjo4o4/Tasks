# Web基础

- 互联网

  **互联网**是 Web 的基石，是让 Web 变得可能的基础设施。本质上来说，互联网是一个大型的相互交流的计算机网络，是把计算机互相连接起来的一个巨大网络。

  - 互联网网址

    因为Internet是计算机的全球网络，所以连接到Internet的每台计算机都必须具有唯一的地址。Internet地址的格式为**nnn.nnn.nnn.nnn**，其中nnn必须是0到255之间的数字，此地址称为IP地址。

    ![](https://i-blog.csdnimg.cn/blog_migrate/35b5387dc093cd8f038aae586410ca8c.gif#pic_center)

    如果通过Internet服务提供商（ISP）连接到Internet，通常会在拨入会话期间分配一个临时IP地址。如果从局域网（LAN)连接到Internet，则计算机可能具有一个永久IP地址，或者可能从DHCP（动态主机配置协议）服务器获得一个临时IP地址。无论如何，如果已连接到Internet，则计算机将具有唯一的IP地址。

  - 协议栈和数据包

    当计算机已连接到Internet，并且具有唯一的地址。它如何与连接到Internet的其他计算机“对话”？

    eg：假设IP地址为1.2.3.4，并且想向计算机5.6.7.8发送消息，要发送的消息是“Hello computer 5.6.7.8”显然，该消息必须通过将计算机连接到Internet的任何类型任何类型的导线进行传输。假设已经从家里拨入ISP，并且该消息必须通过电话线传输。因此，必须将消息从字母文本转换为电子信号，再通过Internet上进行通信，并且通常内置于计算机的操作系统（Windows、Linux等）中。由于使用了两种主要的通信协议，因此Internet上使用的协议栈称为TCP/IP协议栈。TCP/IP堆栈如下所示：

    | 协议层     | 注释                                                         |
    | ---------- | ------------------------------------------------------------ |
    | 应用层     | 特定于应用程序的协议，例如WWW，电子邮件，FTP等               |
    | 传输控制层 | TCP使用端口将数据包定向到计算机上的特定应用程序              |
    | 网络层     | IP使用IP地址将数据包定向到特定计算机                         |
    | 链路层     | 将二进制数据包数据转换为网络信号并返回。（例如，以太网网卡，电话线调制解调器等 |

    如果遵循的路径是消息“Hello computer 5.6.7.8"。从计算机转到IP地址为5.6.7.8的计算机，则会发生以下情况：

    ![](https://i-blog.csdnimg.cn/blog_migrate/e0474e13963994dd85fa16296b4c2f43.gif#pic_center)

    1. 该消息将从计算机上协议栈的顶部开始，然后一直向下运行。
    2. 如果要发送的消息很长，则消息经过的每个堆栈层都可能会将消息分解为较小的数据块。这是因为通过Internet（和大多数计算机网络）发送的数据是以可管理的块形式发送的。在Internet上，这些数据块称为包。
    3. 数据包将通过应用层并继续到TCP层。每个数据包都分配有一个端口号。需要知道目标计算机上的哪个程序需要接收消息，因为它将在特定端口上进行侦听。
    4. 数据包经过TCP层后，将进入IP层。这是每个数据包接收其目的地地址5.6.7.8的地方。
    5. 现在，消息包具有端口号和IP地址，可以随时通过Internet发送。链路层负责将包含消息的字母文本的数据包转换为电子信号，并通过电话线进行传输。
    6. 在电话线的另一端，ISP可以直接连接到Internet。ISP路由器检查每个数据包中的目的地址，并确定将其发送到何处。通常，数据包的下一站是另一个路由器。 
    7. 最终，数据包到达计算机5.6.7.8.在这里，数据包从目标计算机的TCP/IP堆栈的底部开始，然后向上工作。
    8. 当数据包向上通过堆栈时，发送计算机的堆栈添加的所有路由数据（例如端口号和IP地址）都将从数据包中剥离。
    9. 当数据到达堆栈的顶部时，数据包已重新组合成其原始形式”Hello computer 5.6.7.8"。

  - 网络基础架构

    ![](https://i-blog.csdnimg.cn/blog_migrate/4622c8ac4f576f9c585749723987bb24.gif#pic_center)

    在这里，我们看到了图中的更多细节.通过电话网络到ISP的物理连接可能很容易猜到，但是除此之外，还可能是ISP为他们的拨入客户维护一个调制解调器池。这由某种形式的计算机管理，该计算机控制从调制解调器池到骨干网或专用线路路由器的数据流。此设置可以称为端口服务器，因此它“提供”对网络的访问。通常也会在这里收集账单和使用情况信息。

    数据包经过电话网络和ISP的本地设备后，它们将路由到ISP的主干网或ISP购买带宽的主干网。数据包通常会从此处经过多个路由器，并经过多个主干、专用线路和其他网络，直到找到目的地，即地址为5.6.7.8的计算机。

  - 互连网基础设施

    互联网主干网由许多相互连接的大型网络组成。这些大型网络被称为网络服务提供商或NSP。一些大型NSP是UUNet，CerfNet，IBM，BBN Planet，SprintNet，PSINet等。这些网络服务提供商互相交换的数据包流量。每个NSP都必须连接到三个网络访问点或NAP。在NAP处，数据包流量可能会从一个NSP的主干跳到另一个NSP的主干。NSP也可以在城域交换或MAE互连。MAE具有与NAP相同的目的，但它们是私人拥有的。NAP是最初的Internet互连点。NAP和MAE都称为Internet交换点。NSP还将带宽出售给较小的网络

    ![](https://i-blog.csdnimg.cn/blog_migrate/4cee1a627a76dd38a691831ee4e34861.gif#pic_center)
    这不是Internet实际部分的真实表示,只是展示了NSP如何与彼此和较小的ISP互连。图4中没有像图3中那样显示任何物理网络组件。大多数NSP在其网站上发布其网络基础结构的映射，并且很容易找到。由于互联网的规模，复杂性和不断变化的结构，几乎不可能绘制互联网的实际映射。

  - Internet路由器层次结构

    没有计算机知道其他任何计算机在哪里，并且不会将数据包发送到每台计算机。用于将数据包发送到目的地的信息包含在每个连接到Internet的路由器保存的路由表中。

    路由器是分组交换机，路由器通常连接在网络之间，以在它们之间路由数据包。每个路由器都知道其子网以及它们使用的IP地址。路由器通常不知道“在”其上方的IP地址。检查下面的图5。连接主干网的黑匣子是路由器。顶部的较大NSP主干网在NAP处连接。在它们下面是几个子网，在它们下面是更多的子网。底部是两个装有计算机的局域网。

    ![](https://i-blog.csdnimg.cn/blog_migrate/59a2c862be7244e1a30683ab2766da72.gif#pic_center)

    当数据包到达路由器时，路由器将检查原始计算机上IP协议层所放置的IP地址。路由器检查其路由表。如果找到包含IP地址的网络，则将数据包发送到该网络。如果找不到包含IP地址的网络，则路由器会通过默认路由（通常沿主干层次向上到下一个路由器）发送数据包。希望下一台路由器知道将数据包发送到哪里。如果没有，则再次将数据包向上路由，直到到达NSP主干网为止。连接到NSP主干网的路由器拥有最大的路由表，此处数据包将被路由到正确的主干网，从那里开始其“下行”旅程。

- 域名

  Domain Name，又称网域，是互联网基础架构的关键部分,是由一串用点分隔的名字组成的Internet上某一台计算机或计算机组的名称，用于在数据传输时对计算机的定位标识.
  由于IP地址具有不方便记忆并且不能显示地址组织的名称和性质等缺点，人们设计出了域名，并通过网域名称系统（DNS，Domain Name System）来将域名和IP地址相互映射，使人更方便地访问互联网，而不用去记住能够被机器直接读取的IP地址数串。

  当我们浏览网页时，常常会看到形如www.baidu.com这样的网址，而这串内容，就是我们所说的域名。例如：www.baidu.com – 对应的ip地址是14.215.177.38

  - 网站访问方式

    - 通过IP地址访问：可以直接通过网站的IP地址访问。
    - 通过域名访问：域名用于替代IP地址，因为IP地址不易记忆。

  - 域名结构

    ```
    主机名.子域.二级域.顶级域. (根域)
    ```

    ![](https://i-blog.csdnimg.cn/blog_migrate/5864528e2d87958eee2b0936f06f0bea.png)

    以www.baidu.com为例
    `com`为一级域名(即顶级域名，`com`表示公司企业类)；
    `baidu`是二级域名（归属于某个公司自己的域名，一般跟业务有关）；
    `www`是三级域名（`www`代表普通网页）。

    - 根域名 ：`.root` 或者 `.` ，根域名通常是省略的 

    - 顶级域名:是互联网DNS等级之中的最高级的域，它保存于DNS根域的名字空间中。顶级域名是域名的最后一个部分，即是域名最后一点之后的字母。一般是指.com、.net、.org、.com. cn、.cn 等等。例如在 fuyeor.com 这个域名中，顶级域是 .com（或 .COM ），大小写视为相同。

      顶级域名分为国家顶级域名、通用顶级域名、反向域名。

    | 国家顶级域名 | 中国:cn， 美国:us，英国uk…                                   |
    | ------------ | ------------------------------------------------------------ |
    | 通用顶级域名 | com公司企业，edu教育机构，gov政府部门，int国际组织，mil军事部门 ，net网络，org非盈利组织… |
    | 反向域名     | arpa，用于PTR查询（IP地址转换为域名）                        |

    - 二级域名

      二级域名是依附于一级域名（顶级域名）的子域名，它通常用来表示网站的具体页面或者服务。
      例如：
      www.baidu.com www.zhihu.com 里面
      `baidu.`表示百度搜索引擎，`zhihu`表示知乎等。这两个就是二级域名

    - 三级域名

      对于域名所有者/使用者而言，三级域名都是二级域名的附属物而无需单独费用。
      顶级域名“.”的左边部分称为二级域名 （Second-level Domain Name），二级域名的左边部分称为三级域名，以此类推，每一级的域名控制它下一级域名的分配。

      www.baidu.com —— 三级域名，更准确的说叫三级域，其中的`www`就是三级域名
      www.tieba.baidu.com —— 其中的`tieba`就是三级域名，`www`就是四级域名（以此类推）

  - 域名解析

    域名是为了方便记忆而专门建立的一套地址转换系统，要让一台服务器访问互联网，最终还必须通过IP地址来实现，域名解析就是将域名重新转换为IP地址的过程。

    一般一个域名对应一个IP地址，一个IP地址可以对应多个域名；多个域名可以同时被解析到一个IP地址。

    域名解析需要由专门的域名解析服务器(**DNS**)来完成

  - DNS解析过程

    - 步骤：客户端 -> 本地域名服务器 -> 根域名服务器 -> 顶级域名服务器 -> 二级域名/子域名服务器 -> 根据主机名解析出IP地址。

      ![](https://i-blog.csdnimg.cn/blog_migrate/0f1f616696b02c576db92341ac3e41fd.png)

    - 查询方式：递归查询、迭代查询。

- DNS

  1. DNS是什么

     DNS 是 Domain Name System 的缩写，是一种用于将易于记忆的域名，映射到计算机网络中的IP地址的协议，也就是 域名解析系统，它的作用非常简单，就是根据域名查出对应的 IP地址。

     它充当了互联网的"电话簿"，将用户友好的域名转换为计算机能够理解的IP地址，以便正确路由网络请求。比如要访问域名www.163.com，首先要通过DNS查出它的IP地址是112.48.162.8。

  2. 主要功能和特点

     - 域名解析：将域名转换为对应的IP地址
     - 分布式数据库：采用分层分布式架构，提高可靠性和扩展性
     - 缓存机制：减少重复查询，提高解析效率
     - 负载均衡：通过多个IP地址分配请求到不同服务器
     - 冗余备份：提供故障转移能力

  3. 同时使用TCP和UDP协议：DNS可以同时使用TCP和UDP协议来进行通信，具体取决于数据包 的大小和通信方式。

     | 协议    | 使用场景           | 优点                 | 缺点                      |
     | :------ | :----------------- | :------------------- | :------------------------ |
     | **UDP** | 常规DNS查询        | 速度快、开销小       | 数据包大小受限（512字节） |
     | **TCP** | 区域传输、大型响应 | 可靠、支持大数据传输 | 速度较慢、开销较大        |

     在一般情况下，DNS通信采用UDP以提高性能，但当数据包超过UDP限制或需要可靠性时，DNS服务器将使用TCP。这种灵活性使得DNS能够适应各种情况下的通信需求。

  4. DNS查询过程

     当用户在浏览器中输入一个域名（例如，[www.example.com](https://www.example.com/)）并按下回车键时，DNS查询过程如下

     - 本地缓存检查：首先检查本地计算机上的DNS缓存是否包含该域名对应的IP地址
     - 本地DNS服务器查询：如果本地缓存未命中，向本地DNS服务器发送查询请求
     - 根域名服务器查询：本地DNS服务器向根域名服务器查询顶级域DNS服务器地址
     - TLD服务器查询：向顶级域（如.com）DNS服务器查询权威域名服务器地址
     - 权威域名服务器查询：向目标域名的权威域名服务器查询具体IP地址
     - 结果返回：将获得的IP地址返回给用户计算机并缓存结果

     在某些情况下，DNS响应的大小可能超过UDP的最大限制（通常为512字节），此时会使用TCP建立连接，以确保数据的完整性。

  5. 递归和迭代查询的区别

     - 递归

       - 客户端要求DNS服务器必须返回完整的解析结果
       - DNS服务器负责完成所有后续查询工作
       - 适用于客户端与本地DNS服务器之间的查询

     - 查询

       - DNS服务器只返回它能够提供的最佳答案
       - 客户端或DNS服务器需要继续向其他服务器查询
       - 适用于DNS服务器之间的查询

     - 对比

       | 特性         | 递归查询                  | 迭代查询                         |
       | :----------- | :------------------------ | :------------------------------- |
       | **责任方**   | DNS服务器承担全部查询责任 | 查询方承担后续查询责任           |
       | **响应内容** | 返回最终答案              | 返回最佳已知信息或指向其他服务器 |
       | **使用场景** | 客户端到本地DNS服务器     | DNS服务器之间的查询              |
       | **性能影响** | 对服务器资源要求较高      | 分布式负载，资源要求较低         |

  6. DNS记录和DNS报文

     - DNS记录：DNS记录是DNS数据库中的条目，用于存储与域名相关的信息。

       常见DNS记录类型：

       | 记录类型      | 功能描述                 | 示例                                                         |
       | :------------ | :----------------------- | :----------------------------------------------------------- |
       | **A记录**     | 将域名映射到IPv4地址     | [example.com](https://example.com/) → 192.0.2.1              |
       | **AAAA记录**  | 将域名映射到IPv6地址     | [example.com](https://example.com/) → 2001:db8::1            |
       | **CNAME记录** | 创建域名别名             | [www.example.com](https://www.example.com/) → [example.com](https://example.com/) |
       | **MX记录**    | 指定邮件服务器           | [example.com](https://example.com/) → [mail.example.com](https://mail.example.com/) |
       | **TXT记录**   | 存储文本信息，用于验证等 | "v=spf1..."                                                  |
       | **NS记录**    | 指定域名的权威DNS服务器  | [example.com](https://example.com/) → [ns1.example.com](https://ns1.example.com/) |

     - DNS报文：DNS报文是在DNS查询和响应过程中传输的数据包。

       结构：

       - 头部：包含标识符、标志位、问题计数、回答计数等
       - 问题部分：包含要查询的域名和记录类型
       - 回答部分：包含查询的答案（资源记录）
       - 授权部分：指向权威服务器的记录
       - 附加部分：相关的额外信息
